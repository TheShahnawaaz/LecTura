## Exact plan comparison

The saved plan specifies canonical UTC timestamps plus one explicitly labeled service reporting timezone chosen before collection. It does not require arbitrary timezone switching, and warns that changing reporting timezone after pruning raw detail requires a reviewed migration. Fixed UTC is a valid choice within that design; it avoids DST ambiguity but still requires operator confirmation before real collection. No location or timezone is inferred from a learner. Supporting another reporting zone could be added safely before rollout with appropriate split/DST tests and a versioned migration, but silently changing existing day buckets would violate the plan.

The initial cross-course rejection was a conservative restriction, not equivalent to supported multiple memberships. It was a material gap from the plan's integrity goal and could restrict existing imports. It has now been replaced by explicit memberships and preservation tests. Shared playback/download state is global to the video; actual focused duration and transmitted snapshots retain the selected course context.
